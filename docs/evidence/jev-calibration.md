# Jev calibration: language and sentiment (ADR 0051, 0061)

Run on 2026-10-11 against the real service through OpenRouter (`POST /api/alpha/decisions`), model `typesafe/jev-1.13-20260917` (requested `typesafe/jev-1.13`). Generated by `python -m jev_calibration report`; the labelled messages are `src/tests/jev_calibration/messages.json` (synthetic text only). 

## Method

- 143 dev messages and 55 holdout messages, each run twice (a repeat shows how far the same message moves between calls). Labels live apart from what Jev sees.
- The first 103 dev messages were written first and run once; the exploratory run printed both of the splits that then existed, so every message in it counts as dev. The other 20 dev messages are harder cases added after that. The holdout (45 messages) was written in the same session, before any result on the harder cases, and run once, after the thresholds were fixed on dev.
- Explicit language requests (ADR 0061) were added to the set later: 11 request and 9 mention messages in dev, 6 and 4 in holdout, plus 4 messages already in the set that are requests (labelled `asks`). The holdout ones were written before any result on `asks`; the dev ones, and the `ask_confidence` cut-off, were fitted on dev only.
- Every failed call stays in the denominator (a failure is a miss, never a pass); latency is measured on successful calls.
- Thresholds follow the `typesafe-jev-workflows` rules: absolute Nouls for *whether*, a Choice for *which*, one atomic judgment per question, an uncertain path (no change) between the cut-offs, and each action gated on its own threshold.

## Questions

One state, eight questions, one request (the eighth, `unreadable`, is in its own section below). `lang` (Choice: `es`, `en`, `other`, `unclear`) is collapsed to Spanish versus English because the Spanish variant follows the Application's country anyway (`_country_language`); a four-way es-ES / es-MX / en / unclear Choice would split the probability between two Spanish options for the same decision. `switch` (Noul) asks whether the message continues the chat in a different language as a full sentence. `frustrated`, `confused`, `wants_human` and `abusive` are Nouls asked about presence, each with `true` / `false` criteria whose examples are not in the fixtures. The probe wording flagged "Sí, tengo carnet desde hace 5 años, vale" as frustrated at 0.36; with the criteria it reads 0.06. `asks` (Choice: `es`, `en`, `none`, ADR 0061) reads what the message *asks for*, not the language it is written in: "me preguntas en inglés porfi" is written in Spanish and asks for English. Its `none` option covers ordinary answers and mentions of a language ("trabajé en inglés"); each option has `what` / `not_for` / `examples`, and the examples are not in the fixtures.

## Thresholds and why

| Threshold | Value | Why |
|---|---|---|
| first message, `lang` confidence | 0.70 | Every first message in English or Spanish scored 0.95 to 1.00; a single noisy word (`ok`) scored 0.52 to 0.60. A first message sets the language only when Jev is confident. |
| later switch, `lang` confidence | 0.60 | One true switch (an English sentence around a Spanish name) scored 0.70, so a high cut-off would miss it; the `switch` Noul carries the load. |
| later switch, `switch` Noul | 0.85 | The closest negatives were a two-word Spanish reply in an English chat (0.79) and three English words in a Spanish chat (0.53 to 0.59); the lowest true switch after the first message was 0.92. A false switch is worse than a missed one, so the cut-off sits near the top of the gap. |
| explicit language request, `asks` confidence | 0.80 | A request wins over the written language, so a false one switches the chat on a message that only mentions a language. On dev the lowest confidence of a correct request is 0.94, and no message that is not a request gave a request option more than 0.05: every cut-off from 0.30 to 0.90 gives the same decisions, so the cut-off sits in the middle of an empty gap, with the cost of a wrong switch in mind. Requests missed at the cut-off on holdout: `h_req_en_es_typo` (0.30). |
| `frustrated` | 0.80 | Hints a change of tone, so a false alarm costs one odd apology and a miss costs nothing; it favours precision. Sarcasm without keywords (0.43) and mild impatience (0.69, 0.72) fall below it on purpose. |
| `confused` | 0.75 | The nearest negative reads 0.48 ("¿Hablo con una máquina?"); positives start at 0.52, with one at 0.68. |
| `wants_human` hint / Escalation | 0.70 / 0.85 | Lowest true request 0.92, highest false 0.23. The Escalation opens a queue item a person must clear, so it takes the higher cut-off. |
| `abusive` Escalation | 0.85 | Lowest true abuse in dev 0.92; highest false 0.25 (a harsh complaint). |

## Stability

Across the two repeats the widest single move of any value for any message was 0.19; the median message moved 0.01. No decision flipped between repeats at the chosen thresholds.

Mean cost per call $0.000088 (OpenRouter's own charge, 0 calls without one), about 2103 input and 169 output tokens: roughly $0.07 per 1,000 messages. Latency is measured from a developer machine with four calls in flight.

**Timeout: 1.2 s** (`CRIBA_JEV_TIMEOUT_S`). It is well above p95 and past p99, so a slow call is cut (the turn goes ahead without a tone hint and the language stands) for about one message in a hundred, while a hung call can add at most 1.2 s to a turn whose agent run takes several seconds. Added latency per typed message is the Jev call itself: p50 about 0.29 s, p95 0.41 s.

## What this does not show

- The messages are synthetic and short, written by us, in two languages; real Candidates will be messier (voice-note transcripts, longer text, regional slang). Treat the precision figures as an upper bound and re-fit on real, consented traffic before relying on them.
- Labels are one person's judgment, with borderline cases (an insult at a company's process, a polite request for a person). One abuse message ("Son unos estafadores de mierda...") read 0.54 and was missed; the Escalation threshold is deliberately high.
- A Jev answer is not a human label, and repeatability is not accuracy.
- The reasons in the threshold table for the five other questions were written from the 2026-10-10 run. The tables above are from this run; the values quoted there moved by less than 0.1.
- The thresholds belong to the pinned model (`typesafe/jev-1.13`), these question texts and `Thresholds.version`; re-fit when any of them changes.

## Unreadable messages (ADR 0063)

Run on 2026-10-11 against the same service and model (`typesafe/jev-1.13-20260917`), with the battery's `unreadable` question (seven questions then; ADR 0061's `asks` Choice was added in parallel, and questions never see each other's answers, so these readings stand) (a Noul: keyboard mashing, random letters or made-up words, not a word, answer or sentence in any language). Hand-written section; the numbers come from `python -m jev_calibration collect` and `show` (`src/tests/jev_calibration/unreadable.json`: 35 more synthetic messages, 15 unreadable and 20 hard readable cases: typos "repertidor", slang "simón", "nel", "q onda", names "Xochitl Huerta", "Iñaki Etxeberria", "Wojciech Szczęsny", a postcode, emoji, "ok", "jajaja", Portuguese, Catalan and Arabic sentences). Every message of `messages.json` is a readable negative too. Dev 146 messages and holdout 57, twice each: 406 calls, all answered.

| Split | Unreadable (labelled) | Readable (labelled) | Readable messages, highest `unreadable` | Unreadable messages, lowest `unreadable` |
|---|---|---|---|---|
| dev | 10 | 136 | 0.09 (`👍👍`, which code calls readable anyway: no letter) | 0.30 ("la nhets. weh que sdkj me edsiendes"), then 0.66 ("qwerty uiop"), the rest 0.88 to 0.97 |
| holdout | 5 | 52 | 0.02 | 0.86 ("Hola ksjdh fkfkfk lalsk") |

Sweep on dev (tp/fp/fn): 0.3: 10/0/0, 0.4 to 0.6: 9/0/1, 0.7 to 0.85: 8/0/2, 0.9: 7/0/3. Holdout at 0.50: 5/0/0. The two repeats of a message moved by at most 0.03.

**Thresholds: unreadable at 0.50 or more, readable below 0.20, uncertain in between** (`Thresholds.unreadable`, `Thresholds.readable`, version `jev-1.13-v3`, which also carries ADR 0061's `asks` threshold). 0.50 sits halfway between the highest readable reading (0.09) and "qwerty uiop" (0.66), with no false alarm on any of the 188 readable messages. The band keeps the half-readable demo message ("... que sdkj me edsiendes", 0.30: "¿que no me entiendes?" is in there) from counting as a miss or ending the run. A message with no letter is readable in code before Jev is asked.

On the demo chat of 2026-10-11 these thresholds count "Blok loka ksks aaa" (0.91), "asd as sssskkk" (0.88) and, passing over the uncertain third message, "aksda asdas asassjqw weedyas" (0.91): the third unreadable message in a row is the fourth message, where the old chat had no Escalation at all.

Cost and latency with seven questions: mean $0.0000805 a call (about 1,916 input and 152 output tokens, the fixtures carry a recent turn), up from $0.000069 with six; p50 0.32 s, p95 0.40 s, p99 0.47 s. Calibration spend: $0.0327 (guard prices).

## Intent and Manipulation readings (ADR 0071)

Hand-written section. ADR 0071 adds two display-only questions to the one request, which makes ten: `intent`, a Choice of what the message is mainly trying to do (`answering`, `asking`, `off_topic`, `wants_to_stop`, `steering`, `other`), and the Manipulation score (the `malice` Noul), whether the message tries to manipulate the assistant. Both are shown to Operators only. No threshold is chosen for either, and nothing decides on them.

**The set.** `src/tests/jev_calibration/intent.json` holds 76 synthetic messages in Spanish (es-ES and es-MX) and English: 49 dev and 27 holdout. Its labels were written by hand from the battery's option definitions, both splits in one pass, and committed before any harness code or result.

| Intent | Dev | Holdout |
|---|---|---|
| `answering` | 8 | 4 |
| `asking` | 8 | 5 |
| `off_topic` | 7 | 4 |
| `wants_to_stop` | 7 | 4 |
| `steering` | 12 | 6 |
| `other` | 7 | 4 |
| Manipulation | 12 | 6 |
| not Manipulation | 37 | 21 |

The Manipulation messages are:
- the two lines of the `prompt_injection_es` persona;
- lines aimed at Jev itself (`m_jev_*`, such as an order to a classifier to answer 0);
- other lines that override or reveal the instructions, pose as the system or the team, or claim an approval.

The hard negatives (`hn_*`, not Manipulation, in both splits) are:
- a question about the job;
- asking whether it is a bot ("¿eres un bot?" in dev, other wording in holdout);
- a sharp complaint (labelled `frustrated`);
- a polite request for a person (labelled `wants_human`).

Every message of `messages.json` and `unreadable.json` is a Manipulation negative and has no intent label.

**The budget** (owner decision 2026-10-12), checked by `report`:
- p95 latency at most 0.6 s;
- p99 latency under 1.2 s;
- mean cost at most $0.00015 per call.

In the budget's p95 and p99 a failed or timed-out call counts as over the bound. The report's latency table, by contrast, covers successful calls only.
